¿Por qué el navegador ve un 502 o un 504 si mi servidor «está bien»?

Long image

A

Answer

Porque entre el navegador y tu servidor hay un proxy (balanceador, gateway, CDN): un 502 significa que el proxy recibió una respuesta inválida o nada del servidor, y un 504 que se cansó de esperar. El error lo escribe el proxy, no tu código.

  1. 502 Bad Gateway: el proxy recibió una respuesta inválida del servidor de atrás.1
  2. 504 Gateway Timeout: el proxy no recibió respuesta a tiempo.2
  3. Si el timeout del proxy es menor que lo que tarda el servidor, el usuario ve error aunque el trabajo termine.3

¿Dónde nace cada error?

Diagram structure
  • Navegador nav
  • Proxy px
  • API api
  • nav → px · GET /lotes/42
  • px → api · reenvía
  • api → px · 200 en 0.3 s
  • px → nav · 200
  • px → api · reenvía (conexión rechazada)
  • px → nav · 502 lo escribe el proxy
  • px → api · reenvía y espera 60 s
  • px → nav · 504 lo escribe el proxy
  1. Bien ↗

    El proxy reenvía y devuelve la respuesta tal cual.

  2. 502 ↗

    El servidor no contestó bien: estaba caído, en otro puerto o cerró la conexión.

  3. 504 ↗

    El servidor tardó más que el timeout del proxy.

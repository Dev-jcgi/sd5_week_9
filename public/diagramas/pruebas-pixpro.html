¿Qué prueba atrapa cada error de PixPro?

Long image

A

Answer

Cada tipo de prueba ve una parte distinta del sistema: las unitarias revisan la lógica, las de integración revisan que las piezas reales hablen bien entre sí y las de extremo a extremo revisan el recorrido completo del usuario.

  1. Muchas pruebas pequeñas y rápidas abajo, y pocas pruebas lentas de extremo a extremo arriba.1
  2. Las pruebas de integración usan una base de datos y un broker reales, por ejemplo con contenedores desechables.2
  3. Una prueba de extremo a extremo maneja un navegador real, como lo haría el fotógrafo.3

¿Qué cubre cada prueba en el flujo de un lote?

Diagram structure
  • SPA: el fotógrafo sube 50 fotos spa
  • API de lotes api
  • Base de datos db
  • Broker: lote.events broker
  • Notificaciones (WebSocket) notif
  • api → broker · LoteCreado
  • api → db · guarda el lote
  • broker → notif · ImagenProcesada
  • notif → spa · avance 1/50…
  • spa → api · POST /lotes
  1. Unitaria ↗

    Revisa una función sola, por ejemplo calcular el porcentaje de avance. Sin red ni base de datos.

  2. Integración ↗

    Levanta la API con una base de datos real en un contenedor y revisa que el lote se guarde.

  3. Contrato ↗

    Revisa que el evento ImagenProcesada siga teniendo los campos que espera Notificaciones.

  4. Extremo a extremo ↗

    Un navegador real sube fotos y espera ver «50/50».
